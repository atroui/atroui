## Positioning & Messaging

**Primary value proposition**: Opinionated Base UI design system, built in the open for Cal.com; “built for developers and AI.”

**Layering vocabulary**: Primitives → Particles (assembled patterns) → Atoms (API-enhanced / integrated behaviors).

**Target audience**: Teams on Base UI wanting a coherent system beyond raw shadcn ports; Cal.com ecosystem.

---

## Product & Features

- Full primitive suite (dialog, menu, form field, composer, etc.)
- Particles = auth forms, tables, denser app patterns
- Atoms = integrations toward scheduling/auth (Cal.com DNA)
- Origin UI kept as **legacy Radix snapshot** with limited maintenance

### Overlap with AtroUI
- Own-the-files CLI model
- Base UI alignment (AtroUI also Base UI–forward)

### Gaps vs AtroUI
- App/design-system altitude, not dark marketing rooms + Launch/OG tools
- No equivalent Host API BYOK catalog for waitlist/OG/scope
- Licensing story is mixed (AGPL monorepo vs MIT install path) — confuses evaluators

## Implications for AtroUI

- Ally narrative on Base UI / ownership; diverge on **marketing sections + Host APIs + live rooms**.
- Watch “atoms” (API-connected UI) — conceptual cousin to Host APIs; differentiate with BYOK + no keys on atroui.com.
